## Usage

```tsx
import {
  ChatModelMenu,
  ChatModelMenuContent,
  ChatModelMenuEffort,
  ChatModelMenuModels,
  ChatModelMenuTrigger,
} from "@/components/ui/motif/chat-model-menu";

export function Composer() {
  const [model, setModel] = useState("deepseek-v4-flash");
  const [effort, setEffort] = useState<ReasoningEffort | null>(null);

  return (
    <ChatModelMenu
      effort={effort}
      models={MODELS}
      onEffortChange={setEffort}
      onValueChange={setModel}
      value={model}
    >
      <ChatModelMenuTrigger />
      <ChatModelMenuContent>
        <ChatModelMenuModels />
        <ChatModelMenuEffort />
      </ChatModelMenuContent>
    </ChatModelMenu>
  );
}
```

## Not the Model Select

[Model Select](/docs/media/model-select) is for a catalogue: dozens of generation models
from many makers, searched and indexed. This menu is for the handful of chat models a
conversation can run on, where the second question matters as much as the first. How hard
should it think?

## The steps follow the model

Each vendor tells a different set of thinking steps apart. DeepSeek offers `off`, `low`,
`high` and `max`. Gemini Flash offers `low` to `high`. Claude offers `low` to `max` and
cannot be turned off. So a model declares its own steps and its default.

```tsx
{
  id: "claude-sonnet-5-5",
  name: "Claude Sonnet 5.5",
  provider: "anthropic",
  family: "anthropic",
  thinking: { options: ["low", "medium", "high", "xhigh", "max"], default: "high" },
}
```

The thinking control is one row under the models that opens a submenu of the steps of
the model in use. Folded away, the steps never set the menu's height, so switching models
leaves it the same size. A model with one step or none draws no row, and its separator
goes with it.

## The pick is a wish

The user's step is held as they chose it, not rewritten to fit each model. Pick `max` on
Claude, switch to Gemini, and the trigger reads `Medium`, Gemini's default. Switch back
and it reads `Max` again. `effortOf(model, effort)` resolves the step a turn should run
at, so the server and the trigger agree.

## The protocol lock

A conversation stores its history in one protocol's shape. Gemini keeps thought
signatures, Anthropic keeps its own blocks. So after the first turn it can only move
between models of the same `family`. Pass that family and the other models stay in the
list, disabled, under a heading that names the reason.

## Parts

| part                   |                                                                        |
| ---------------------- | ---------------------------------------------------------------------- |
| `ChatModelMenu`        | Owns the model and the step. Draws only the menu shell.                |
| `ChatModelMenuTrigger` | Mark, name, step, chevron. `children` replaces the face.               |
| `ChatModelMenuContent` | The panel. Opens upward, because a composer sits at the window's foot. |
| `ChatModelMenuModels`  | The model list. `label` and `lockedLabel` name its heading.            |
| `ChatModelMenuEffort`  | A row that opens the thinking steps. Nothing when there is no choice.  |

## Accessibility

Both lists are Radix radio groups, so arrow keys move through them and screen readers
announce the checked row. The trigger's label names the model and the step together.
Every mark is decorative, because the name sits beside it.
